# cidaren

词达人的本地网页工具。在 Windows 上启动命令窗口和浏览器，通过网页获取鉴权信息，
选择班级或自学任务运行，并管理本地词库。支持单次执行、循环到满分、停止任务、查看日志
和可选的大模型兜底。

## 安装与首次启动

准备以下环境：

- Windows，以及用于打开词达人学生端的 PC 微信。
- Anaconda 或 Miniconda；项目使用 `cidaren` 环境中的 Python 3.12。
- Git for Windows，以及 `origin` 仓库的推送权限。首次迁移和词库维护需要上传并核验备份。

在准备存放项目的目录打开 PowerShell：

```powershell
git clone https://github.com/qianjiyi/cidaren.git
cd cidaren
.\安装依赖.bat
```

[安装依赖.bat](安装依赖.bat) 会查找 Conda，创建或复用 `cidaren` 环境，将 Python 调整为
3.12，安装项目及运行依赖并运行 `pip check`。首次安装还会从 [.env.example](.env.example) 创建
`.env`；已有配置会保留。依赖及版本范围见 [pyproject.toml](pyproject.toml)，其中
mitmproxy 固定为 `11.0.2`。Conda 不在常见目录时，可先从 Anaconda Prompt 运行脚本，
或将 `CONDA_EXE` 设置为本机 `conda.exe` 的路径。

在当前仓库配置提交身份并登录 Git：

```powershell
git config --local user.name "你的GitHub用户名"
git config --local user.email "你的GitHub noreply邮箱"
git credential-manager github login
```

邮箱应填写 GitHub 账号设置中显示的完整 noreply 地址。登录账号必须能向 `origin` 推送。
仅克隆公开仓库并不会获得写入权限；没有本仓库权限时，先在自己的账号建立可写仓库或
Fork，再执行 `git remote set-url origin <你的仓库地址>`。远端地址不要包含 Token 或密码。
维护命令使用已保存的 Git 登录信息，运行时不会弹出登录窗口。

首次使用内置题库时，关闭网页和任务，再执行：

```powershell
.\词库管理.bat migrate
.\点我启动.bat
```

迁移会先上传原始输入到 `backups` 分支，再建立 `data/lexicon.sqlite3`。重复执行不会重新
导入已迁移数据。未手动迁移时，启动程序也会尝试迁移；网络、登录或推送失败会中止，
保留输入。已有运行词库的项目不需要再次迁移。

[点我启动.bat](点我启动.bat) 会自动打开浏览器，服务仅监听 `127.0.0.1:5001`。可访问
`http://127.0.0.1:5001` 或启动时打开的 `http://localhost:5001`；端口占用时命令窗口会报错。
关闭服务可在命令窗口按 `Ctrl+C`。

## 网页获取 Token 与运行任务

1. 确认没有运行、排队、启动核验或等待重启的任务，点击“获取 Token”。
2. 在 PC 微信中打开词达人学生端，进入会请求 `app.vocabgo.com` 的页面。
3. 等待网页提示鉴权验证成功，配置和任务列表会自动刷新。
4. 默认进入“班级任务 → 可执行”，选择可继续的班级学习或测试任务；需要自学时主动切换到“自学任务”。学习和自学可点击“启动”或“循环”；测试只单次启动或继续，完成后停止。
5. 在任务面板查看日志、分数和状态，使用“停止”结束任务及后续循环。

任务运行状态每约 1.5 秒从本机读取，远端任务和分数通常每 30 秒在后台刷新，也可手动刷新。
列表接口立即返回缓存和刷新状态；首次加载可能先显示空列表，后台读取后自动更新。
同一服务的多个网页共享一次远端刷新，慢请求期间仍可停止任务、查看日志和切换分类。
远端读取失败时保留上次列表和本机任务；切换账号后的旧响应不会覆盖新账号列表。
页面只更新变化的任务行；日志按游标增量读取，最多保留最近 500 行。
状态区分排队中、正在确认资格、运行中、等待重启、停止中、已停止、已完成和失败。
排队和启动核验期间也可停止，失败详情保留在日志中。
修改程序源码后，先停止任务并关闭启动窗口，再重新启动并刷新浏览器，以加载更新。

默认最多同时执行 4 个任务，启动前的账号与任务核验也占用名额。学习和自学共用队列，
超出的任务依次等待；一键循环会加入队列。每轮正常结束后先释放名额，未满分且资格仍有效
时等待 5 秒，再回到队尾。测试任务不排队：名额已满时拒绝启动，需要稍后手动重试。
调小并发数不会终止已有任务，后续启动遵循新上限。更换鉴权会取消待启动任务和后续循环；
修改自学课程或难度会取消对应的待启动自学任务和循环。退出服务会取消队列并停止子进程，
重启不会自动恢复队列。并发上限适用于当前网页服务实例。

任务面板通过“班级任务”和“自学任务”两个页签分开查看和操作，每次打开或刷新网页都
默认进入“班级任务 → 可执行”。两个来源各自保留“可执行”和“已结束”分类，列表、
分类数量和操作按钮仅对应当前来源；同名班级任务和自学词表的分数、状态分别显示。
班级页提供“一键循环班级学习任务”，自学页只提供单条任务操作，需要主动切换后执行。
班级分类直接读取词达人学生端相同的 `PageTask` 筛选：`search_type=0 / 1 / 2` 分别为
全部、进行中、已结束。只有官方已结束的任务进入“已结束”；其余任务显示在“可执行”。

“可执行”是尚未结束任务的入口，实际启动资格显示在每一行。满分、尚未开放、截止、
权限不明、暂停待核对、PK 或未知类型会显示原因并限制启动。进度、分数、本机进程结束
和本次测试完成标记不改变官方分类。学习进度 100% 但未满分时仍可继续；测试进度达到
或超过 100% 时须在官方端核对，本程序不重开。

官方读取失败时保留上次分类并标记过期；没有已确认分类的任务显示在“可执行”页，行内
标注“状态待确认”。自学列表没有官方结束分类，也显示在“可执行”页，满分时禁用启动。
测试必须取得新鲜的官方进行中状态，开放时间、权限及分数／进度均确认后才能启动。

班级截止时间按服务器的开始时间加任务时长计算，并以北京时间显示。普通学习任务进度
100% 但分数不足 100 时，在有效期内仍可继续。任务列表没有次数字段时，不推断剩余次数。
服务器未返回的本机任务保留停止和日志入口，显示待确认，刷新并确认资格前不能重新启动。

切换来源页签或状态分类只改变显示，不会停止或删除任务；另一来源有运行或等待重启的
任务时，会显示数量和切换入口，切换后可查看日志、停止任务或人工恢复。当前状态分类
隐藏了运行中的任务时也会显示提醒。满分或截止任务仍可查看已有日志、停止已有进程。
启动、循环和人工恢复前会检查当前来源；迟到的请求响应只更新对应任务，不切换页签或
自动打开另一来源的日志。批量循环只处理执行状态为“程序可运行”的班级学习任务，始终跳过自学和测试；
每轮重启前再次检查资格，已满分、截止、类型或权限不明时停止循环。远端刷新失败时保留
上次列表，标记状态来自上次成功读取，并重新计算执行期限；实际提交结果以服务器判定为准。

学习和自学再次启动时，服务器存在可继续的练习就直接继续；需要选词时使用普通练习参数，选择未满分
单词，不自动强制重置选词或开启会员错题模式。程序检查选词提交结果，失败时显示服务器
返回码和原因；答题入口、验证和保存的业务错误也会结束本轮，并停止循环，避免反复重启。
如果继续状态已失效并明确返回“需要选词”，仅尝试一次重新读取列表和普通选词。

所有入口（网页、CLI、任务子进程及直接调用答题函数）会重新读取服务器账号和任务归属。
班级类型 `1` 执行学习流程，类型 `2` 执行测试流程，自学类型为 `3`。PK、未知类型或归属
不符会在答题前拒绝。测试不会调用学习选词、重置或签到接口，普通学习函数也不能接收
测试。调用参数不能改变服务器上的任务类型。正常学习和自学仍可
循环到满分；只有正常结束的一轮才考虑继续，任何非零退出或分数查询失败均停止循环。
更换鉴权后也会停止后续循环，刷新账号和任务后再手动启动。

词达人只读网络请求最多尝试三次，基础退避为 0.5 秒、1 秒，并加入少量随机等待；服务端
提供 `Retry-After` 时按其要求等待，超出等待预算则停止重试。选词提交、创建任务、开始答题、验证和
保存及测试跳题均只发送一次，不通过重启整轮重试。非阅读题只有服务器明确确认验证结束才保存，
使用验证后最新题码；完整学习阅读题直接保存一次。每题验证次数有上限；普通学习多选未完成、
字段异常、题码回环或下一题不完整都会停止，不因进度或已答题数达到总数就推断完成。
测试无可用答案时的处理见下文。

## 测试任务

测试提供单次启动／继续、停止和日志，不提供循环，批量学习循环会跳过测试。
尚未开始的测试会在首次进入时取得正式任务编号；只有官方状态、权限、零分零进度均确认时才允许初始化。
首次响应无法确认任务编号或完整题目时暂停核对，不会自动再次初始化；取得正式编号后仍保留同一任务的停止和日志入口。
启动请求明确发送 `task_type=2`，本次答题收到服务器 `20004` 或 `20006` 后停止并持久
保存结束标记。这个标记不会把官方尚未截止的任务改成“已结束”，也不会修改服务器进度。

支持 19 种基础题型：普通选择、搭配多选、组词、父子选项及拼写。父子选项生成官方组合
标签，多空拼写发送按空顺序排列的字符串数组。长题型码保留原值，按前两位选择处理规则。
测试查询同一词库，依次使用精确题库、缓存、跨任务词库、规则和模型；新增题型先精确复用。
测试不使用学习流程的猜测兜底，没有可用答案时等待时限并跳题。
只有服务器确认正确的答案进入已验证缓存，多选必须完整验证；跳题和未验证纠错不学习。
服务器明确结束本题后，答错也按实际结果保存并继续，不反复重考来提高分数。

| 每题限时 | 基础题型 |
| --- | --- |
| 10 秒 | 15、17、18 |
| 15 秒 | 16、21、22 |
| 20 秒 | 11、32 |
| 25 秒 | 31、41、42、51、52 |
| 30 秒 | 43、44 |
| 35 秒 | 13、53、54、73 |

普通题发送验证时停止倒计时，多选题持续到本题验证结束。模型等待受剩余时间限制，迟到
结果会丢弃；词库未命中且模型超时，或合法媒体题无法处理时，到时调用官方跳题接口继续，
跳题可能影响分数。未知题型、损坏数据或不完整题目会暂停核对。保存和跳题使用验证后最新
题码，验证、保存及跳题串行执行；正在等待提交响应时不会另发跳题请求。
每个测试进程只保留一个模型建议工作线程，最多等待一个后续建议，避免模型慢响应时
不断创建线程和并发请求。过期建议会跳过，模型线程不能提交答案或操作词库。

`20005` 提示尚未开始；`21006` 表示需要人工验证码，程序暂停。请在官方端完成验证、
核对并处理当前题目后再重新同步，不会自动重发原请求。停止程序不保证服务器计时暂停。

## 异常暂停与人工恢复

程序在 `data/task_runtime/` 保存独立的运行安全记录，并使用跨进程任务锁。记录按服务器
账号编号的哈希及班级 `release_id`，或自学课程和 `list_id` 绑定；同账号更换 Token 或
任务编号不会绕过暂停。记录仅保存必要哈希、操作和时间，不包含凭据或完整题码，不进入
Git 词库备份。同一轮继续已有练习时沿用题码记录，确认新的选词或自学任务后才建立新轮。
运行安全格式 v2 兼容已有 v1 记录，保留原暂停和题码；新增测试结束标记及题目计时起点。
重启继续时扣除已耗时间，时钟异常时暂停。人工同步不清除测试结束标记或已处理题码。

可能推进状态的请求发出前先写入待确认记录；完整检查响应后才确认。超时、断连、解析
失败、强制退出或记录写入失败都会保守停止。退出码 `0` 为正常结束，`1` 为其他执行错误，
`2` 为任务状态错误，`3` 为提交结果需核对。异常退出不会自动循环，重启服务仍保留暂停。
失败日志会区分请求／解析失败和响应校验失败，并记录异常类型、诊断码及必要的响应结构。
这些诊断不保存服务器原文、题目、答案或凭据；更新前的待确认记录不会被补造为已确认。

网页显示“需核对提交状态”时：

1. 在词达人官方学生端核对该任务的实际提交结果和当前练习状态。
2. 回到网页，点击“核对后重新同步”，明确确认已经完成核对。
3. 程序取得任务锁，只读刷新账号与任务，解除对应的暂停。不会重放请求或自动开始答题。
4. 检查刷新后的任务资格，需要继续时再手动点击启动或循环。

恢复保留本轮已经尝试过的题码。如果重新启动后服务器仍回显旧题码，程序会再次停止；
请先在官方端核对并处理该题、推进到新题后再同步。仅收到但尚未验证或保存的下一题
不算已处理，正常停止后可以继续。

账号不符、网络失败、过期恢复标识或损坏记录会拒绝恢复并保留暂停。不要删除安全记录
来绕过保护。安全记录属于本机运行状态，正在处理异常时不要仅从 Git 词库备份迁移任务。
已有异常统计不会被重置或修正；本次保护仅作用于更新后启动的进程。升级时先停止旧任务、
关闭命令窗口，再重新启动程序并刷新浏览器，旧进程不会自动获得这些保护。

获取成功后由用户手动启动任务。配置中心也支持手动填写鉴权字段。获取期间暂停任务列表
自动刷新并禁止启动任务；可点击“取消获取”，默认等待时间为 120 秒。

获取程序从同一请求读取完整的 `USERTOKEN`、`ABC`、`AUTH_V`，同时保存 `USER_AGENT`。
缺少鉴权字段会继续等待，避免混用不同请求的新旧字段。程序先恢复代理，再调用账号信息
接口验证；验证通过才一次性保存配置，失败时显示原因并保留原配置。

首次获取会在 `.capture/mitmproxy/` 生成项目专用证书，并检查、安装当前 Windows 用户的
证书信任。HTTPS 捕获需要微信客户端信任该证书。获取期间临时使用 `127.0.0.1:8888`
代理，仅解析目标主机的相关请求。成功、取消、超时、后台异常和服务退出均尝试恢复代理；
异常退出后的恢复记录在下次启动时检查。只有当前代理仍属于本次获取时才恢复，其他程序
期间修改的代理会保留。获取状态接口和普通日志不返回完整凭据。

## 配置

配置中心与项目根目录 `.env` 使用相同字段。优先级为：进程环境变量 → `.env` → 默认值。
网页保存采用临时文件替换；任务子进程继承更新后的配置。

| 字段 | 用途 |
| --- | --- |
| `USERTOKEN`、`ABC`、`AUTH_V` | 词达人鉴权，需完整填写 |
| `USER_AGENT` | 获取时的微信 User-Agent，传给客户端和任务进程 |
| `COURSE_ID` | 自学课程，默认 `CET4_v2` |
| `STUDY_GRADE` | 自学难度，默认 `2` |
| `LLM_URL` | OpenAI 兼容接口地址 |
| `LLM_MODEL` | 大模型名称 |
| `LLM_KEY` | API Key，留空禁用大模型兜底 |
| `MAX_CONCURRENT_TASKS` | 当前网页服务的并发任务上限，默认 `4`，可设 `1` 到 `8` |
| `VOCABGO_PROXY_MODE` | 词达人请求路线：`direct` 直连（默认）、`system` 系统代理、`custom` 指定代理 |
| `VOCABGO_PROXY_URL` | 仅指定代理模式生效，填写 `http://` 或 `https://` 地址 |
| `LLM_PROXY_MODE` | 模型网关路线，选项同上，默认 `direct`，与词达人独立 |
| `LLM_PROXY_URL` | 模型网关的指定 HTTP(S) 代理地址 |

`.env.example` 的鉴权和密钥均为空。实际 `.env` 只保存在本机，Git 不负责恢复这些配置。
旧配置没有新增字段时自动使用 4 并发、两条路线直连。保存代理或模型配置后，新任务使用
新配置；已有子进程沿用启动时的配置，需要停止并重新启动该任务才能切换。

直连模式忽略系统／环境代理；系统代理模式采用 Requests 的环境／系统代理解析；指定
代理模式只使用填写的地址。三种模式都保留 HTTPS 证书验证。网关不稳定时，可分别调整
两条路线，无需改变 Windows 的全局代理。获取 Token 时临时代理的恢复规则保持不变。

词达人客户端和模型请求分别复用会话连接，结束时释放。连接超时设为 5 秒，词达人读取
超时为 20 秒，普通模型读取超时为 45 秒。词达人只读请求最多尝试 3 次，普通模型请求
最多 2 次；只有连接类错误以及 HTTP `429/502/503/504` 才重试。`401/403`、证书错误、
无效 JSON 或响应结构错误直接报错。先检查 HTTP 状态，再解析响应，避免 HTML 错误页
掩盖网关故障。普通模型重试等待预算为 90 秒，词达人只读请求为 65 秒；测试模型每题
只尝试一次，并受该题剩余时间限制。预算用于限制重试和丢弃迟到结果；底层读取超时
不是整个请求的硬性总时长，测试主流程独立执行题目截止时间。

网络诊断写入本机 `data/diagnostics/network.jsonl`，约每 1 MiB 轮转，最多保留当前文件及
两个旧文件。诊断只记录时间、进程、服务、操作、路线、尝试次数、HTTP 状态、错误类型
和耗时，不包含代理地址、凭据、题目、答案或服务器响应正文；诊断写入失败不阻止任务。
提交结果不明时仍会暂停待核对，不会靠自动重发推进任务。

## 词库查询与答案学习

运行词库位于 `data/lexicon.sqlite3`，使用 Python 内置 SQLite。内置
[cidaren/bank.json](cidaren/bank.json) 有 7612 条原始记录，是首次迁移输入，运行时不再写入。
迁移保留全部原文；当前可推导 7601 条候选，11 条答案可能截断，保留并报告问题。
候选索引会去重，其记录数量可能与原文数量不同。历史候选需要再次验证，不能直接等同于
已确认的正式答案。

查询顺序固定为：

```text
正式精确题库 → 已验证临时缓存 → 跨任务词库 → 规则 → LLM → 猜测兜底
```

跨任务查询先使用已入库知识，再尝试完整且上下文兼容的历史候选。选择题保存答案文字，
在当前选项中重新映射真实 `answer_tag`，支持选项换序和非连续标签。文字重复、答案冲突
或映射不唯一时继续回退。句子题保留语境，组词保留顺序及词数，填空区分模板、完整短语
与空格答案；未知题型只支持精确匹配。规范化保留词边界、否定、词性和词形，不进行模糊合并。

规则和大模型答案先进入待验证缓存，服务器明确判定正确后才允许入库。纠错响应经过类型
检查与答案映射，未经确认的结果继续待验证。多选题只有完整答案集合通过验证后才可入库。
阅读阶段的官方释义也进入缓存，多个词义分别保留。

缓存默认不自动过期。手动入库会在同一事务内更新正式记录、知识索引并移除对应缓存；
冲突答案保留，无法消歧时回退。服务器否定的应用关系会被停用并记录纠错，避免持续复用
已知错误。各任务读取最新提交的数据，避免内存快照覆盖其他进程的更新。

日志标记 `[精确题库]`、`[临时缓存]`、`[正式词库]`、历史候选、规则、大模型或猜测。
`[词库未命中]` 与 `[LLM回退]` 提示会解释未命中的原因。

## 缓存入库与管理脚本

双击 [词库管理.bat](词库管理.bat) 打开交互菜单，也可在项目目录执行：

| 命令 | 操作 |
| --- | --- |
| `.\词库管理.bat status` | 查看正式库、缓存、待验证和历史数据统计 |
| `.\词库管理.bat preview` | 预览新增、重复、冲突及不可转换项 |
| `.\词库管理.bat preview --limit 0` | 显示全部记录 |
| `.\词库管理.bat promote --ids 12,15` | 将指定的已验证记录入库，ID 来自预览 |
| `.\词库管理.bat promote --all` | 将全部已验证缓存入库，跳过待验证或已否定记录 |
| `.\词库管理.bat clear-cache` | 确认并备份后清理缓存，保留正式库和历史数据 |
| `.\词库管理.bat backup` | 上传当前源码及完整词库快照 |
| `.\词库管理.bat export .\词库导出.json` | 显式指定路径，手动导出版本 JSON |
| `.\词库管理.bat restore git:backups` | 恢复远端最新词库快照 |
| `.\词库管理.bat restore git:<提交SHA>` | 恢复备份分支历史中的指定快照 |
| `.\词库管理.bat restore .\词库导出.json` | 从版本 JSON 或 SQLite 文件恢复 |

CLI 等价入口为 `conda run --no-capture-output -n cidaren python -m cidaren.bank_tools`，
在后面添加相同参数即可。`export` 不指定路径时执行 Git 备份。清理和恢复默认要求输入
`YES` 确认，自动化调用可显式添加 `--yes`。首次迁移和恢复要求网页及任务全部停止。

首次迁移、入库、清理缓存和恢复现有数据库前，会先上传并核验 Git 备份。网络、登录、推送
或核验失败时取消维护，保留原数据。上传期间出现新写入，维护操作也会取消并提示重试。
入库和清理不会自动启动任务；缓存清理不影响正式记录、历史原文和错误关系停用记录。

## Git 备份与恢复

`main` 已合并运行源码、脚本、项目配置、文档、许可证、内置 `bank.json`，以及
`backup/lexicon.json` 中的完整词库快照。`backups` 继续保存后续自动及手动备份，通过普通
提交历史保留各版本。运行数据写入 `data/lexicon.sqlite3`；保存最新学习结果时仍执行
`backup`，跨电脑优先使用 `restore git:backups` 恢复最新备份。

每次完整备份包含 `backup/lexicon.json` 和 `backup/manifest.json`；首次迁移备份包含
`backup/legacy-input.json`。SQLite 备份接口生成一致快照，版本 2 JSON 保存六张业务表、
自增序号和格式版本。下载时核对清单和 SHA-256，恢复前检查结构、完整性和版本，损坏数据
会报错。恢复只替换运行词库，不切换源码，也不改本机鉴权。

日常答题写入缓存时不会逐条上传。需要保存最新学习结果时执行 `backup`；维护操作则会
自动备份。程序不自动生成本地备份文件；显式指定路径的 `export` 仍可使用。Git 自身的
对象和历史保存在 `.git/`。未登录时先运行 Git Credential Manager 登录，再重试维护。
两台电脑同时备份可能导致一次普通推送被拒绝，重试前查看最新备份，避免覆盖其他电脑的进度。

当前 GitHub 仓库公开，`backups` 中的完整词库和缓存也公开。上传排除实际 `.env`、密钥、
证书、代理恢复记录、日志、SQLite 数据库、运行锁、测试代码及产物和任务截图。运行目录
只保留运行、安装及词库管理所需文件。已有提交和标签保留，历史词库备份仍可恢复。
恢复兼容版本 1 JSON 和 SQLite 文件；版本 1 没有保存自增序号，会按现存记录重建。

## 跨电脑使用

在新电脑安装 Conda、Git，克隆 `main`，配置具有推送权限的 Git 登录，然后执行：

```powershell
git clone https://github.com/qianjiyi/cidaren.git
cd cidaren
.\安装依赖.bat
# 在此配置当前仓库的提交身份、Git 登录及可写 origin
.\词库管理.bat restore git:backups
.\点我启动.bat
```

已有远端完整快照时，先恢复再启动即可保留正式库、缓存、历史数据和验证记录；无快照时
执行首次迁移。新电脑在网页重新获取 Token，并按需填写大模型配置，证书信任由新电脑
检查。GitHub 下载的 ZIP 不含 `.git/`，无法直接完成自动备份，建议使用 Git 克隆。

也可以关闭网页和任务后，将整个项目目录（包括隐藏的 `.git/`、本机 `.env` 和 `data/`）
私下复制到另一台电脑，再运行安装脚本。脚本按自身所在目录定位文件，无需固定盘符或
用户名；Conda 环境不随项目复制。证书与代理恢复记录属于本机状态，直接复制时不带
`.capture/`，让目标电脑首次获取时重新生成。

## 运行检查

在项目目录运行：

```powershell
conda run --no-capture-output -n cidaren python -m pip check
conda run --no-capture-output -n cidaren python -m cidaren.bank_tools status
```

第一条检查依赖是否兼容，第二条校验运行词库并显示记录统计。首次迁移未完成时先执行
`migrate`；词库损坏时程序报错，不会自动创建空库覆盖。启动网页后，可通过配置中心与
任务面板检查鉴权和日志。Token 获取需要在 PC 微信中打开词达人，检查证书信任、请求
捕获和任务刷新。
