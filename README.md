# cidaren 词达人整合版

这个项目把网页版任务控制台和 Token 获取流程放到同一个本地网页中：启动程序、点击获取
Token、在 PC 微信中打开词达人学生端，鉴权验证成功后即可选择任务运行。

项目可以放在任意目录。任务接口、HTTP 请求头、配置、答题逻辑、题库、任务调度和
测试都以 `cidaren-main` 网页版为基线。桌面版只用于参考 Token 获取流程，
不使用它的界面、答题逻辑、网络请求模块、spaCy 模型或旧版 EXE。

## 功能

- 在网页中自动获取并验证 `USERTOKEN`、`ABC`、`AUTH_V` 和 `USER_AGENT`。
- 展示并运行班级任务和自学任务。
- 支持单次执行、循环到满分、批量启动班级任务、停止任务和查看日志。
- 使用本地 SQLite 精确题库、临时缓存和跨任务词库，支持预览和手动入库。
- 保留可选的 OpenAI 兼容大模型兜底。
- Token 获取结束、取消、超时、异常退出时恢复原系统代理。

## 运行环境

项目使用名称为 `cidaren` 的 Conda 环境，要求 Python 3.12。脚本不包含用户名或 Conda
安装目录的绝对路径，可以把整个项目复制到其他 Windows 电脑和任意目录。

安装脚本会依次从当前 Conda 配置、系统 `PATH`、用户目录和系统目录中查找 Anaconda 或
Miniconda。目标电脑需要先安装其中一种；如果 `cidaren` 环境不存在，脚本会自动创建。
主要依赖如下：

| 依赖 | 版本要求 | 用途 |
| --- | --- | --- |
| Flask | `>=3.1,<4` | 本地网页和 API |
| requests | `>=2.32,<3` | 词达人及大模型请求 |
| certifi | `>=2024.8.30` | HTTPS 证书链 |
| mitmproxy | `==11.0.2` | 获取鉴权字段 |
| pytest | `>=8.3,<10` | 开发测试，可选 |

首次使用请双击 [安装依赖.bat](安装依赖.bat)。安装脚本会创建或复用 Conda 环境
`cidaren`，把可编辑安装指向脚本所在项目，并运行依赖一致性检查。

## 启动与使用

双击 [点我启动.bat](点我启动.bat)。程序默认监听：

```text
http://localhost:5001
```

启动脚本会自动打开浏览器。如果 5001 端口已占用，命令窗口会显示明确错误。

使用步骤：

1. 确认当前没有正在运行或等待循环重启的任务。
2. 点击网页顶部的“获取 Token”。
3. 在 PC 微信中打开“词达人 → 学生端”，进入任意会访问 `app.vocabgo.com` 的页面。
4. 等待网页显示“鉴权已保存并验证成功”。
5. 在任务面板选择任务，点击“启动”或“循环”。

获取成功后程序只刷新配置和任务列表，不会自动开始答题。鉴权也可以在配置中心手动填写。

## Token 获取过程

获取功能使用独立后台进程，流程如下：

1. 检查 8888 端口、运行任务和重复获取状态。
2. 在项目的 `.capture\mitmproxy` 目录生成独立证书，并检查当前 Windows 用户是否已信任。
3. 备份当前用户的 Windows 代理配置，然后临时设置为 `127.0.0.1:8888`。
4. 仅处理 `app.vocabgo.com`，其他主机由 mitmproxy 直接转发，不读取其请求内容。
5. 从同一个请求获取完整的 `USERTOKEN`、`ABC`、`AUTH_V` 和 `USER_AGENT`；字段缺失时继续等待。
6. 先停止抓取并恢复代理，再使用网页版 `Client` 的 `/Student/Main` 请求验证账号。
7. 验证通过后原子写入 `.env`；验证失败时保留原配置。

默认等待 120 秒。状态 API 和普通日志都不返回或打印完整鉴权字段。

mitmproxy 解密 HTTPS 需要客户端信任其独立 CA 证书，原理和证书说明见
[mitmproxy 官方文档](https://docs.mitmproxy.org/stable/concepts/certificates/)。

## 代理恢复

程序在更改代理之前写入 `.capture\proxy-recovery.json`。正常完成、取消、超时、后台进程异常
或 Web 程序退出时都会尝试恢复。下次启动也会检查尚未完成的恢复记录。

恢复操作只在当前代理仍是本次设置的 `127.0.0.1:8888` 时执行。如果获取过程中其他程序
修改了代理，程序不会覆盖该修改，并在 `.capture\last-proxy-recovery.json` 记录结果。

## 配置

运行配置保存在项目根目录的 `.env`：

| 字段 | 说明 |
| --- | --- |
| `USERTOKEN` | 词达人用户 Token |
| `ABC` | 词达人 `abc` 请求头 |
| `AUTH_V` | 词达人 `authorization-v` 请求头 |
| `USER_AGENT` | 获取时使用的微信 User-Agent |
| `COURSE_ID` | 自学课程 ID，默认 `CET4_v2` |
| `STUDY_GRADE` | 自学难度，默认 `2` |
| `LLM_URL` | OpenAI 兼容接口根地址 |
| `LLM_KEY` | 大模型 API Key；留空则禁用兜底 |
| `LLM_MODEL` | 大模型名称 |

配置优先级为：进程环境变量、`.env`、程序默认值。网页保存配置时使用临时文件替换，避免只
写入一半导致配置损坏。任务子进程会继承同一套配置。

## 词库与临时缓存

运行数据保存在项目相对目录 `data/lexicon.sqlite3`，使用 Python 内置 SQLite，没有新增第三方
依赖。`cidaren/bank.json` 保留为历史迁移备份，升级后不再向它写入。鉴权、请求地址、代理配置
及任务调度沿用网页版现有实现。

查询顺序固定为：

```text
正式精确题库 → 已验证临时缓存 → 跨任务词库 → 规则 → LLM → 猜测兜底
```

精确记录保存完整题型、题干、备注、选项内容及原始 `answer_tag`，并保留存在的图片、音频
标识。LLM 和规则输出先保存为待验证候选；服务器明确判定正确后才成为可入库缓存。阅读
阶段的官方释义也进入缓存，保留多个词义。服务器纠错仅作为待验证候选；单独收到纠错提示
不等于答案已经通过验证。多选题需要每个答案都正确、达到所需数量且服务器确认结束，才
能把完整答案集合标记为可入库。

新知识不会自动写入正式库，缓存也不会自动过期。相同完整题目可以直接使用已验证缓存；
手动入库后，同一语境或模板下的答案能跨任务复用。选择题保存答案文字，再映射到当前
选项的真实 `answer_tag`，不把编号当作选项位置。选项换序不影响兼容的正式词库记录。

词库只规范化显示性空白、大小写和明确的标点变体；英文词边界、否定、词形、词性和模板
内容仍保留。句子题保留整句及备注；组词题保留顺序和词数；填空题区分完整短语与空格
答案。未知题型只作精确匹配，带图片或音频的题目也只作完整精确匹配。

多个词义分别保存；同一条件下的冲突答案全部保留。当前选项能唯一消歧时使用对应答案，
无法消歧、重复文字、字段不完整或上下文不兼容时继续回退。服务器否定某次匹配后会记录
并停用该答案在当前条件下的应用关系；清理缓存不会解除这种停用。任务每题读取最新已
提交数据，写入使用短事务和锁等待，不再将整个内存题库覆盖回文件。

### 首次迁移与历史数据限制

先关闭网页服务及全部任务，再运行：

```powershell
.\词库管理.bat migrate
.\词库管理.bat status
```

新版本首次启动也会在网页监听端口之前完成迁移。旧服务仍在运行时，首次迁移会报错。
新网页和任务进程会持有运行锁，阻止恢复或尚未完成的迁移与其同时执行。异常退出遗留的
锁文件在进程结束后不再占用。

当前 `bank.json` 共 **7612 条原始记录**，兼容三种旧键格式。重新检查得到 **7601 条可推导
候选记录、11 条正确选项可能截断的记录**。全部原文都保存在 SQLite 的历史区；无法转换
或可能截断的记录列在预览报告中，不补造丢失信息。候选索引可能去重，因此独立索引数与
原始记录数不一定相同；`status` 分别报告 `legacy`、`legacy_candidates` 和 `historical`。

本次实际迁移得到 `historical=7600`，其中一条推导候选与其他记录重复，原文仍全部保留。
初始 `formal=0`、`cache=0`，新缓存从升级后开始积累。`conflicts` 包含历史知识中同一词或
条件下的多个答案，也包含多义词，并不等于错误题目数量。

这些历史候选没有新的完整验证证据，只在上下文兼容、答案完整且映射唯一时试用。旧句子
记录缺少备注时，不会借用新题目的备注。历史候选通过服务器再次验证后生成完整缓存，
仍需手动入库，不能把全部历史记录直接当成正式知识。

迁移前会校验输入，将原文件及当前源码上传至 Git `backups` 分支并核验，再在事务中导入。
首次迁移需要安装 Git、配置提交身份及 GitHub 登录；上传失败时不会开始迁移。
迁移标记保存原文件 SHA-256 和记录数；重复执行不会重复导入，也不会覆盖后续学习数据。
数据库或 JSON 损坏时会明确报错，不会静默新建空库。

### 预览、入库和清理

双击 [词库管理.bat](词库管理.bat) 可进入菜单，也可以在项目目录执行命令：

| 命令 | 用途 |
| --- | --- |
| `.\词库管理.bat status` | 查看历史、正式库、缓存、待验证数量及冲突 |
| `.\词库管理.bat preview` | 预览缓存中的新增、重复、冲突、待验证项及历史不可转换项，每类最多30条 |
| `.\词库管理.bat preview --limit 0` | 查看全部预览记录 |
| `.\词库管理.bat preview --ids 12,15` | 查看指定缓存记录 |
| `.\词库管理.bat promote --ids 12,15` | 将指定已验证记录入库 |
| `.\词库管理.bat promote --all` | 入库全部已验证记录，跳过待验证和已否定记录 |
| `.\词库管理.bat clear-cache` | 输入 `YES` 确认后，先备份，再清理缓存 |
| `.\词库管理.bat backup` | 将当前源码和完整词库上传至 Git `backups` 分支，并返回提交 SHA |
| `.\词库管理.bat export` | 不指定路径时同样执行 Git 备份，不生成本地备份文件 |
| `.\词库管理.bat export "D:\备份\词库.json"` | 导出到指定位置 |
| `.\词库管理.bat restore git:backups` | 从最新 Git 备份恢复词库，输入 `YES` 确认 |
| `.\词库管理.bat restore git:提交SHA` | 从 `backups` 历史中的指定提交恢复词库 |
| `.\词库管理.bat restore "D:\导出\词库.json"` | 从显式导出的版本 JSON 或 SQLite 文件恢复 |

ID 来自 `preview`，上表的 `12,15` 只是示例。入库结果报告 `promoted`、`skipped` 和 `conflicts`；
冲突答案分别保留，重复记录合并。正式记录与知识索引更新、对应缓存移除处于同一事务，
任何一步失败都会回滚。入库、清理和恢复前会自动上传 Git 备份；失败时取消维护操作。
上传期间若任务写入了新数据，入库或清理会取消并提示重试，保护快照之后新增的缓存。

清理只删除缓存，正式数据、历史原文和错误匹配停用记录保留。自动化维护可使用
`clear-cache --yes` 或 `restore 路径 --yes` 明确确认；双击菜单默认要求交互确认。

直接使用 CLI 的等价入口为：

```powershell
conda run --no-capture-output -n cidaren python -m cidaren.bank_tools status
```

### 备份恢复与跨电脑复制

备份统一保存在 [GitHub 的 backups 分支](https://github.com/qianjiyi/cidaren/tree/backups)。每次
提交包含当前源码、`backup/lexicon.json` 和校验清单；首次迁移前则保存原输入
`backup/legacy-input.json`。`main` 和原有备份标签不受影响。本机 SQLite 数据库继续运行，
Git 自身的对象和提交历史保留在 `.git`；程序不再生成 ZIP、bundle 或 `data/backups/` 副本。

SQLite 备份接口先生成内存中的一致快照，版本 2 JSON 包含六张业务表、自增序号及数据库
格式版本。下载时核对文件清单与 SHA-256，恢复前检查完整性和版本；先将当前数据备份
到 Git，再替换。恢复必须关闭网页及所有任务。旧版 JSON 和 SQLite 文件仍可恢复；旧版
JSON 没有自增序号，按现存最大记录 ID 重建。恢复只替换词库，查看旧源码可另行克隆相应提交。

安装 [Git for Windows](https://git-scm.com/downloads/win)，在项目目录配置提交身份，例如：

```powershell
git config user.name "你的GitHub用户名"
git config user.email "你的提交邮箱"
git credential-manager github login
.\词库管理.bat backup
```

使用 Git Credential Manager 保存登录。维护命令不会弹出登录窗口；未登录、网络故障、推送
被拒绝或校验失败都会明确报错并保留原词库。推送不使用强制覆盖；两台电脑同时备份时，
失败的一方重试即可。每个 Git 命令最多等待60秒。一般答题和缓存写入不会逐条上传 Git，
需要保存最新学习结果时手动执行 `backup`；入库、清理、恢复和首次迁移前自动备份。

当前仓库为公开仓库，备份包含完整词库和缓存；`.env`、Token、API Key、证书和日志排除。
这些配置仍在本机维护，不会从 Git 恢复。

新电脑安装 Git 和 Conda 后，可以执行：

```powershell
git clone --branch backups https://github.com/qianjiyi/cidaren.git
cd cidaren
.\安装依赖.bat
.\词库管理.bat restore git:backups
.\点我启动.bat
```

在网页重新获取 Token 并填写大模型配置。也可以关闭程序后复制整个项目目录，或使用显式
指定路径的 `export` JSON。管理脚本沿用便携 Conda 发现逻辑，不依赖原电脑用户名或安装路径。

### 答题日志

日志显示 `[精确题库]`、`[临时缓存]`、`[正式词库]`、`[历史词库候选]`、`[历史精确候选]`、
`[规则]`、`[LLM]` 或 `[猜测]`。进入大模型之前会输出 `[词库未命中]` 的具体原因和
`[LLM回退]` 提示，便于区分完全没有记录、上下文不兼容、映射歧义或旧答案已被否定。

## 本地 API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/auth/capture/start` | 开始获取鉴权 |
| `GET` | `/api/auth/capture/status` | 返回状态和提示，不返回凭据 |
| `POST` | `/api/auth/capture/cancel` | 取消获取并恢复代理 |
| `GET/POST` | `/api/config` | 读取或保存配置 |
| `GET` | `/api/tasks` | 读取班级和自学任务 |
| `POST` | `/api/start` | 启动单个任务 |
| `POST` | `/api/start_all` | 循环启动全部未满分班级任务 |
| `POST` | `/api/stop` | 停止任务 |
| `GET` | `/api/logs` | 读取任务日志 |

鉴权获取接口只接受回环地址和本机同源页面请求。获取期间任务列表暂停刷新，所有任务启动
接口返回冲突状态。

## 测试

测试全部围绕网页版、Token 获取衔接和 SQLite 词库，不使用桌面版答题代码：

```powershell
conda run -n cidaren python -m pytest -q
```

覆盖内容包括完整字段传递、字段缺失、验证失败、取消、超时、代理恢复、重复启动、任务
冲突、本机同源限制、状态脱敏、网页版 Client 传参和配置读写。词库测试另外覆盖旧格式
迁移、截断、非连续 `answer_tag`、选项换序、多义词、组词顺序、填空模板、多选完整性、
错误停用、并发写入、入库幂等、事务回滚、版本导出和恢复。Git 测试使用本机临时仓库，
覆盖推送失败、远端核验、历史提交恢复、凭据排除及上传期间新增数据保护，不上传测试数据。

`a vicious cycle`、`derive from`、`attribute … to …` 的模拟任务先验证学习和手动入库，再
更换任务与选项，确认命中正式词库时不调用 LLM。班级、自学、循环、停止、日志和配置
使用模拟客户端回归；测试不调用真实任务或大模型接口。

实机验收还需要在 PC 微信中打开一次词达人，以确认当前微信版本能正常信任证书、产生请求
并刷新任务列表。测试不会自动启动真实答题任务。
